# UX do Onboarding

## Layout

### Mobile

Conteúdo diretamente na página, sem card decorativo apertando a largura.

CTA principal pode ficar próximo ao rodapé quando isso não atrapalhar teclado/campos.

### Desktop

Conteúdo centralizado e relativamente estreito. Não juntar várias etapas apenas porque há espaço horizontal.

## Progresso

Exibir progresso por quatro grandes blocos:

1. Seu negócio
2. Sua agenda
3. Sua IA
4. WhatsApp

Não usar “Etapa 7 de 18”.

## Navegação

- `Voltar` disponível;
- progresso salvo por etapa concluída;
- fechar navegador não deve perder etapas já confirmadas;
- ao retornar, abrir próxima pendência;
- não mostrar sidebar/bottom navigation da área logada.

## Uma decisão por tela

É regra preferencial, não dogma.

Dois campos pequenos e intimamente relacionados podem compartilhar tela, como:

- segmento;
- nome pelo qual clientes conhecem o negócio.

Evitar separar artificialmente cada input em uma tela própria.

## Scroll

Primeiro tentar reduzir complexidade/dividir decisões quando a tela ficou longa.

Se o conteúdo realmente exige scroll, permitir scroll natural. Nunca:

- reduzir fonte;
- comprimir espaçamento excessivamente;
- prejudicar legibilidade;

apenas para “não ter scroll”.

## Visual

Usar recursos visuais para deixar o onboarding agradável:

- ícones por etapa;
- ilustrações/assets pontuais;
- animações de sucesso;
- transições leves;
- estados de conexão;
- demonstração da IA animada;
- progresso do teste real.

Visual deve apoiar compreensão e sensação de acabamento, não criar distração.

## Demonstração

A demonstração automática é um ponto de encantamento do onboarding.

Ela deve parecer uma conversa viva, usando dados reais do negócio, com eventos do sistema discretos e animações rápidas.

Não deve parecer vídeo longo ou tutorial passivo.

## Teste real

A tela de teste deve usar animações/progresso para mostrar que o sistema está validando o fluxo completo.

Deve ser possível alternar para o WhatsApp no celular e voltar sem perder estado.
